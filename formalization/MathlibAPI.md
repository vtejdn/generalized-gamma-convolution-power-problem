## Current compatibility and evidence conventions

- The accepted project boundary is standard logic plus E-S1. Local E-B1/E-B3,
  bounded Markov-Krein, J2/J3 and T1 proofs are implemented; general unbounded
  J1 and the unused Thorin converse are retired. API-074/079 are withdrawn
  from construction scope, not proved representations.
- API-070/072/076 public J2/J3 compatibility is accepted on the corrected
  **measurable-only** types and fresh historical expression comparisons in
  [A-F01](AcceptanceReport.md#f01). Earlier topology-preservation acceptance
  claims are withdrawn; the independent finding and missing post-repair
  auditor recheck remain in [AuditReport](AuditReport.md#f01).
- API evidence levels are `to_find -> source_read -> #check_passed ->
  minimal_use_compiled`. Design acceptance (`pending / accepted /
  needs_revision`) and auditor coverage are separate states. A compiled API
  application does not by itself prove its full consumer.
- Pins: Lean **4.32.2**, mathlib
  **`905b95818eb32af7874a58b427f50c1711a5e96c`**. Library paths below are relative
  to `.lake/packages/mathlib/Mathlib`. Recheck full types, signs, shapes/rates,
  measurable structures, null sets and hypotheses before a new application.
- Entries retain original construction/use evidence counts with immutable Git
  pointers. Those are historical observations, not current-build claims or
  independent-auditor sign-offs. Current acceptance is only in AcceptanceReport.
  Full update diaries live in Git, not appended here.
- Prefer tracked production uses over duplicate probes. Use [Checks](Checks/README.md)
  for durable design/delivery evidence; ignored experiments alone do not
  establish an adopted interface. Negative searches state inspected scope,
  closest rejected candidate, exact mismatch and a useful re-search trigger.

Initialization labels **R10** and **M1** refer to the historical pinned-source
reuse review and designer M1 acceptance in
